# Live environment

Record of every change the programme makes in the live Fabric tenant and Azure subscription:
what, when, why, and how to undo it. No secrets, tokens or tenant data are recorded here.

Rules (from the programme brief):

* Everything created is prefixed `fabricops-` / `FabricOps Sandbox` and tagged
  `owner=fabricops-programme`, `purpose=sandbox|dev|test|prod` (`purpose=shared` for resources used
  by every environment, such as the container registry). Entra applications carry the same
  information in their `notes` field. Fabric capacity names allow only
  lowercase letters and digits, so capacities use `fabricops` without the hyphen.
* Existing workspaces and resources not created by the programme are never modified, read for
  data, or granted access. Reading the metadata of a workspace approved for monitoring is allowed.
* The runtime never uses the owner's identity. The owner's Global Administrator sign-in is used for
  bootstrap only, after explicit approval of each change.
* The teardown script (`scripts/live-estate/teardown.sh`, added in WS5) is kept idempotent and
  current with this log.

## Sandbox estate (WS5)

Built and removed by `scripts/live-estate/create.sh` and `teardown.sh` (idempotent, `az rest` + `curl`, no other
dependency; see [development.md](development.md#live-sandbox-tests-against-a-real-fabric-tenant) for the commands).
Everything lives on the existing F4 capacity `fabricdemocap2026` (Australia East, `RG-FABRICDEMO`, USD 0.84/h while
running, decision D8), which also hosts four workspaces that do not belong to the programme: the scripts read its
state, resume it and suspend it, nothing else, and **pause it again whenever the live work is idle** (the capacity was
Paused when WS5 started).

| Workspace | Items | Purpose |
|---|---|---|
| `FabricOps Sandbox [DEV]` | lakehouse `crm_source` with Delta table `customers` (50 synthetic rows) and `customers_clean`; notebooks `seed_customers`, `transform_customers`; pipeline `ingest_customers` | DEV environment; its lakehouse also carries the read-only OneLake role for the test principal |
| `FabricOps Sandbox [TEST]` | the same | TEST environment; fault target for `seed-history.sh`; the control with no OneLake role |
| `FabricOps Sandbox [PROD]` | the same | PROD environment; its `customers_clean` feeds the consumer model |
| `FabricOps Sandbox Consumer` | semantic model `customers_model` (Direct Lake over PROD's `customers_clean`), report `customers_report` | the downstream consumer |

Also: the connection `fabricops-sandbox-fake-source` (type `WebForPipeline`, Basic credential `fabricops-fake` /
`not-a-real-secret`, base URL the tenant's Microsoft Entra token endpoint; it is deliberately invalid and is used only
by `inject/auth-failure.sh`), the Viewer role for `fabricops-live-reader` on the four workspaces, and the OneLake data
access role `fabricopsDeltaLogReader` on the DEV lakehouse (`Read` on `Tables/customers`, nothing else). All data is
generated by `seed_customers` ("Customer 0001", fixed countries and segments); nothing is copied from anywhere.

Item ids are tenant data and are not recorded here: `scripts/live-estate/status.sh` prints them, and
`scripts/live-estate/contracts.sandbox.json` (git-ignored) is generated from them.
